## 1. Executive Summary

This document establishes the binding, non-negotiable architectural constraints and engineering invariants governing all subsystems of **OVIC EON**.

These constraints are not aspirational guidelines; they are deterministic, verifiable engineering rules enforced through static analysis, automated linting gates, CI test suites, and runtime policy verifiers. Any implementation PR violating an invariant established herein is rejected by automated CI gating.

---

## 2. Invariant Classification Scheme

Each constraint is identified by a unique, structured identifier:
- `CONST-DEP`: Dependency & Hierarchy Constraints
- `CONST-SAF`: Safety & Actuation Constraints
- `CONST-PRV`: Privacy & Data Protection Constraints
- `CONST-PERF`: Execution & Performance Constraints
- `CONST-MSG`: Event & Messaging Constraints
- `CONST-FLT`: Fault Isolation & Reliability Constraints

## 3. Dependency & Architectural Hierarchy Constraints (`CONST-DEP`)

### `CONST-DEP-001`: Strict Acyclic Layer Dependency (DAG)
- **Statement:** The layer dependency graph must form a strict Directed Acyclic Graph (DAG) directed from top to bottom (L10 -> L1), or horizontally mediated by the L5 Core Event Bus.
- **Rule:** Lower layers (`L1`, `L2`, `L3`) are strictly prohibited from importing or referencing higher layers (`L4`, `L5`, `L8`, `L9`). No layer may introduce a circular dependency.
- **Enforcement:** Enforced in CI via `import-linter` and `ruff` circular dependency audits.

### `CONST-DEP-002`: Engine Decoupling and Isolation
- **Statement:** No intelligence engine in L4 may hold a direct reference to, or invoke a method on, another intelligence engine instance.
- **Rule:** All inter-engine communication must occur asynchronously via the L5 Core Event Bus using typed `EventEnvelope[T]` instances.
- **Enforcement:** Static code analysis scans `src/eon/engines` ensuring zero cross-engine package imports (e.g., `eon.engines.ers` cannot import from `eon.engines.ere`).

### `CONST-DEP-003`: Local-First Substrate Independence
- **Statement:** Core runtime execution must not require external cloud network connectivity.
- **Rule:** Zero mandatory calls to external web APIs or cloud services during inference, reasoning, or response generation.
- **Enforcement:** Network socket isolation sandbox tests run with `eth0` disabled.

## 4. Safety & Actuation Constraints (`CONST-SAF`)

### `CONST-SAF-001`: Non-Authoritative Actuation Invariant
- **Statement:** OVIC EON is an emotional intelligence and social reasoning infrastructure; it has zero direct physical motion authority over robot actuators.
- **Rule:** Every event, intent, proposal, or advice emitted by EON must preserve `is_authoritative_stop=False`. EON cannot command motor PWM, CAN velocity frames, or release emergency brakes.
- **Enforcement:** Pydantic schema validation validator rejects any outgoing event with `is_authoritative_stop=True`.

### `CONST-SAF-002`: Advisory-Only Output Demarcation
- **Statement:** All speech, viseme, screen display, and gesture plans emitted by EON are advisory recommendations submitted to the robot host's certified safety controller.
- **Rule:** The robot manufacturer's certified safety controller (ISO 13849-1 / ISO 10218-1) retains absolute override authority to clamp, suppress, or discard any proposed gesture that violates physical obstacle corridors.
- **Enforcement:** Documented and verified in all interface control agreements and integration adapters.

### `CONST-SAF-003`: Anti-Deceptive Transparency Invariant
- **Statement:** EON must not simulate synthetic claims of biological consciousness, physical sentience, or medical diagnosis.
- **Rule:** Responses generated by ERG must not claim subjective human feelings (e.g. `"I feel actual physical pain"` or `"I am legally diagnosing your clinical depression"`).
- **Enforcement:** Grammar-constrained decoding and regex safety filters reject anthropomorphic deception.

## 5. Privacy & Data Protection Constraints (`CONST-PRV`)

### `CONST-PRV-001`: Zero Raw Biometric Media Persistence
- **Statement:** Raw video frames from cameras and raw PCM audio waveforms from microphones must never be persisted to persistent storage (hard disk, flash memory, or database).
- **Rule:** Raw sensor data is ingested exclusively into volatile RAM circular buffers in L2/L3 and must be zero-wiped immediately following feature extraction.
- **Enforcement:** Automated filesystem write audits during soak tests verify zero multimedia file creation.

### `CONST-PRV-002`: Ephemeral-by-Default Session Memory
- **Statement:** Long-term episodic memory is strictly optional and consent-gated.
- **Rule:** If explicit user consent is absent, all interaction memories expire and are purged from volatile RAM upon session termination (`InteractionStage.FAREWELL` or timeout).
- **Enforcement:** Session cleanup tests verify zero residual state in memory after session end.

### `CONST-PRV-003`: Verifiable Cryptographic Erasure (GDPR Article 17)
- **Statement:** When an authorized user requests data deletion, EON must coordinate verifiable destruction.
- **Rule:** Personal preference records are encrypted using per-user symmetric keys. Deletion destroys the user key (`CryptoShredder`), rendering any backup blocks permanently unrecoverable, alongside executing hard database row deletion.
- **Enforcement:** Verification test suite attempts recovery after key destruction and confirms zero readable plain text.

### `CONST-PRV-004`: Sensitive Attribute Exclusion from Logs
- **Statement:** System logs, traces, and metrics must never contain raw user utterances, transcripts, or biometric landmarks.
- **Rule:** Logging formatters must scrub all fields marked `DataClassification.RESTRICTED` or `DataClassification.CONFIDENTIAL`.
- **Enforcement:** Log analysis filter tests verify zero PII leakage under debug log levels.

## 6. Execution & Performance Constraints (`CONST-PERF`)

### `CONST-PERF-001`: CPU-First Execution Baseline
- **Statement:** The complete baseline EON pipeline (L1 through L9) must execute in real time on a 4-core edge CPU (ARM64 Cortex-A76 or x86_64 Core Ultra 5) without mandatory GPU or NPU acceleration.
- **Rule:** Hardware accelerators (NPUs, GPUs) are treated strictly as optional performance optimizers; fallback CPU implementations must exist for all model adapters.
- **Enforcement:** Automated CI performance runners run with GPU/NPU drivers completely disabled.

### `CONST-PERF-002`: Real-Time Latency Budgets
- **Statement:** End-to-end conversational response latency must remain within human conversational comfort thresholds.
- **Budgets (Reference: 4-core Cortex-A76 @ 2.4 GHz):**
  - Core Event Bus median dispatch latency: $\le 0.100\text{ ms}$
  - Visual Perception (Face Mesh + AUs): $\le 20.0\text{ ms}$
  - Acoustic VAD & Emotion Feature Extraction: $\le 30.0\text{ ms}$
  - Cognitive Empathy Reasoning (ERE CPM): $\le 15.0\text{ ms}$
  - Turn-Taking Floor Acquisition (SIE): $\le 350.0\text{ ms}$
  - Surface NLG Time-to-First-Chunk (ERG): $\le 350.0\text{ ms}$
  - Neural TTS Audio Synthesis Time-to-First-Buffer: $\le 80.0\text{ ms}$
- **Enforcement:** Measured continuously in automated performance benchmark regression tests.

### `CONST-PERF-003`: Bounded Memory Footprint
- **Statement:** Total resident memory (RSS) of the core EON runtime must remain within bounded edge limits to prevent OOM termination.
- **Limits:**
  - Idle Resident Memory: $\le 150\text{ MB}$
  - Active Conversational Memory (excluding SLM weights): $\le 450\text{ MB}$
  - Total System Memory (including quantized SLM & TTS): $\le 1800\text{ MB}$
- **Enforcement:** Continuous memory profiling during 24-hour soak qualification tests.

## 7. Event & Messaging Constraints (`CONST-MSG`)

### `CONST-MSG-001`: Universal Event Envelope Encapsulation
- **Statement:** Every message exchanged across the L5 Core Event Bus must be an instance of `EventEnvelope[T]`.
- **Rule:** Bare dictionaries, unvalidated JSON strings, or arbitrary Python objects are strictly rejected by `EventBus.publish()`.
- **Enforcement:** Runtime type validation in `EventBus.publish()` raises `InvalidEventError` on non-envelope instances.

### `CONST-MSG-002`: Bounded Queue Capacity & Backpressure
- **Statement:** Every subscriber queue must have a finite, configured capacity (default: 1000 items).
- **Rule:** Unbounded queues are strictly prohibited to prevent memory exhaustion under slow consumers. Under queue saturation, the configured policy (`WAIT`, `REJECT`, `DROP_OLDEST`) must be deterministically applied.
- **Enforcement:** Bounded queue manager unit tests verify eviction and rejected metrics under saturation.

### `CONST-MSG-003`: Synchronous Handler Threadpool Isolation
- **Statement:** Synchronous subscriber handlers must never execute directly on the `asyncio` event loop thread.
- **Rule:** Synchronous handlers must be offloaded to a bounded `ThreadPoolExecutor` (default: 4 workers), preventing event loop blocking.
- **Enforcement:** Automated tests verify that a synchronous handler containing `time.sleep(1.0)` does not delay asynchronous event dispatch.

## 8. Fault Isolation & Reliability Constraints (`CONST-FLT`)

### `CONST-FLT-001`: Blast Radius Containment
- **Statement:** An unhandled exception, syntax error, or crash inside any perception pipeline or intelligence engine must not crash the L5 Core Event Bus or terminate the main process.
- **Rule:** Subscriber handler execution is wrapped in robust exception handlers; failures decrement component health without interrupting core routing.
- **Enforcement:** Chaos testing suites inject exceptions into individual engine event handlers and verify system survivability.

### `CONST-FLT-002`: Deterministic Fallback on Model Failure
- **Statement:** If an ML model runtime (ONNX, `llama.cpp`, Piper) fails or exceeds its execution deadline, the engine must fall back to a deterministic heuristic within $<10\text{ ms}$.
- **Rule:** The engine must never hang or produce unhandled errors; it must emit a valid fallback response.
- **Enforcement:** Simulated runtime failure injection during dialogue generation tests verifies immediate template fallback.

### `CONST-FLT-003`: Graceful Shutdown Drain Guarantee
- **Statement:** Upon receiving `SIGTERM` or `stop()`, the runtime must drain all pending safety and context events before closing queues.
- **Rule:** Graceful shutdown drains queues up to `shutdown_timeout_seconds` (default: 5.0s), preventing truncated state transitions.
- **Enforcement:** Shutdown drain regression tests verify zero lost events during orderly termination.
